# YCFMG 建设对话记录

> 本文件记录 YCFMG 从需求到可运行版本的完整过程，与源码一同存放。
> 版本：fmg2609.001 ｜ 记录时间：2026-09-30

## 一、需求（用户原话要点）

1. 制作一款「文件管理 + 图库」结合的应用，形态包含 fpk、二进制、Docker；
2. 支持飞牛 NAS、通用 NAS、VPS 等设备；需为全新自研源码；
3. 支持以图搜图、以文搜图与自动分类；同时具备完整文件管理功能；
4. 界面像 Windows 资源管理器；文件管理与图库两者的优缺点要均衡结合；
5. 支持分享，并拥有专属分享页；支持绑定多个域名作为链接；
6. 源码与本对话存放到 `/vol1/1000/DSH空间/YCFMG`；应用名 `YCFMG`；
7. Logo 要简洁而非文字；
8. 版本号规则：`fmg2609.001`，26 = 年份，09 = 月份，001 = 当月修改次数；
9. 交付通道：飞牛 NAS SSH（192.168.1.8）、GitHub 令牌、Docker Hub 账号。

| 项 | 结果 | 影响 |

| 目标目录 | 已存在且为空 | 直接作为仓库根 |
| Go 工具链 | 未安装，go.dev 可达 | 下载 go1.27.1 到仓库内 `.tools/`，缓存全部重定向到仓库内 |
| Node / pnpm | 已安装 | 仅用于前端语法自检（`node --check`），运行时不依赖 |

| GitHub API | 返回 403（出口受限） | 推送脚本已就绪，实际推送取决于网络放行 |

## 三、关键技术决策

1. **Go 单二进制**：NAS 场景下无运行时依赖，fpk 与容器体积最小，交叉编译无 cgo。
2. **纯 Go SQLite**（modernc.org/sqlite）：避免 cgo，静态链接，交叉编译一次通过。
3. **图像检索不依赖模型**：以 pHash/dHash/aHash + 颜色直方图做以图搜图；
   以「中文分词 + 同义词扩展 + 字段加权打分」做以文搜图；模型路径改为可选的 CLIP 端点。
   理由：NAS 上的内存与体积约束，且零配置即可用。
4. **前端零构建**：原生 HTML/CSS/JS，`go:embed` 打入二进制，`git clone` 后可直接 `go build`。
5. **分享页服务端渲染**：分享链接必须能被任意浏览器直接打开，首屏不依赖 JS 框架。
6. **文件零搬迁**：数据库只存可重建的派生数据，删除数据库后重新索引即可恢复。

## 四、实施过程（按阶段）

| 阶段 | 产出 |
| --- | --- |
| 1 | 目录骨架、VERSION、.gitignore、Logo（文件夹 + 照片意象的几何标志，无文字） |
| 2 | `config`（含自研 YAML 子集解析器）、`logx`、`util` |
| 3 | `store`：SQLite 模式与全部数据访问（文件、分享、用户、会话、标签、任务、向量） |
| 4 | `vision`：感知哈希、颜色直方图、主色与色系命名、EXIF 解析、规则分类与自动标签 |
| 5 | `thumbs`：多尺寸缩略图缓存（含 ffmpeg 兜底） |
| 6 | `indexer`：增量扫描、按需索引、定时任务、丢失标记与标签重建 |
| 7 | `search`：以文搜图、以图搜图、重复图聚类、语义端点适配 |
| 8 | `auth` / `media` / `share`（含分享页渲染与多域名） / `fsapi` |
| 9 | `server`：约 50 个 HTTP 接口与前端静态资源服务 |
| 10 | 前端：Win 风格资源管理器 + 图库瀑布流 + 搜索中心 + 分享管理 + 设置 |
| 11 | 打包：Dockerfile、compose、fpk 清单与生命周期脚本、构建/推送/部署脚本 |
| 12 | 端到端验证与文档 |
